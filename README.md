# Помощник сертификата ТПП

Локальная программа переносит данные из клиентской заявки Word в макет сертификата происхождения на платформе ТПП. Перед заполнением она показывает все распознанные значения, проверяет отсутствие кириллицы и позволяет проверить готовый PDF.

## Запуск

На компьютере с Codex достаточно дважды щёлкнуть `start.cmd`. Скрипт использует локальный Node.js и библиотеки из среды Codex.

Для независимой установки потребуется Node.js 20 или новее:

```powershell
npm install
npm start
```

Программа откроется по адресу `http://127.0.0.1:3210` в отдельном профиле Microsoft Edge. Профиль хранится в `data/browser-profile`; логин и cookie платформы не передаются программе и не записываются в JSON заявки.

## Рабочий порядок

1. Выберите заявку `.doc` или `.docx`.
2. Проверьте поля 1–12. Жёлтые сообщения обозначают значения, которые были переведены или выведены из контекста.
3. Укажите полный URL платформы и нажмите «Открыть платформу».
4. Войдите в систему и откройте нужный пустой макет.
5. Вернитесь на вкладку помощника и нажмите «Проверить поля страницы». Этот отчёт нужен для первой калибровки селекторов реальной платформы.
6. Нажмите «Заполнить форму» и визуально проверьте макет.
7. После проверки нажмите «Сохранить и скачать PDF».
8. Загрузите скачанный PDF в четвёртом шаге для контрольной сверки.

## Что реализовано

- чтение DOCX и текстовых заявок Word 97–2003 DOC;
- извлечение экспортёра, получателя, транспорта, маршрута, контрактов, товаров, упаковки и веса;
- перевод и нормализация текста для английского сертификата;
- блокировка заполнения при наличии кириллицы;
- редактируемый экран предварительной проверки;
- сохранение структурированных данных в `data`;
- управление установленным Edge или Chrome через Playwright;
- поиск полей по подписям на русском и английском языках;
- сохранение и скачивание PDF при стандартных названиях кнопок;
- проверка PDF на кириллицу и наличие ключевых значений.

## Ограничения первой версии

Фактические `id`, `name` и структура повторяющихся товарных строк на платформе пока неизвестны. Универсальный адаптер ищет элементы по видимым подписям и уже работает на форме, повторяющей показанный макет. После получения отчёта «Найденные элементы страницы» адаптер можно точно настроить под реальный HTML, включая кнопки добавления строк и внутренние списки типов веса.

По умолчанию указан официальный личный кабинет ТПП РФ `https://lk.tpprf.ru/docflow/`. Адрес можно заменить в интерфейсе, если рабочий макет открывается на другом домене.

Старые DOC могут сильно различаться внутренней структурой. Формат исходной заявки проверен локально; сам клиентский документ и его реквизиты в репозиторий не входят. DOCX остаётся наиболее надёжным входным форматом.
